# Skeleton-Based Human Action Recognition

تعرّف على أفعال الإنسان من الهيكل العظمي (skeleton) — تدريب على NTU RGB+D 60
واستنتاج على فيديو عادي.

## الفكرة

```
فيديو ──► YOLOv8n-pose ──► 17 نقطة COCO ──► تطبيع ──► نوافذ زمنية
                                                          │
NTU-60 (ntu60_2d.pkl, pyskl) ──► نفس التطبيع ──► BiLSTM ──┘
                                                          │
                                    softmax ──► معايرة حرارية ──► تنعيم
                                                          │
                                             عتبة رفض ──► 'other'
```

الموديل بيتدرّب على هياكل NTU الاتنين-بعدية بس (`ntu60_2d.pkl` من pyskl)،
والاستنتاج بيشتغل على أي فيديو عن طريق YOLO-pose. المفتاح إن **التطبيع
والعيّنة الزمنية لازم يبقوا متطابقين بالظبط بين التدريب والاستنتاج**.

## الكلاسات العشرة

| label | الحركة | | label | الحركة |
|---|---|---|---|---|
| 0 | drink_water | | 27 | phone_call |
| 7 | sit_down | | 33 | rub_hands |
| 8 | stand_up | | 34 | nod_head |
| 9 | clap | | 39 | cross_hands |
| 22 | wave | | 43 | touch_head |

الكلاسات دي **مختارة على مقاس فيديوهات الاختبار، مش على أساس F1 على NTU**.
ده أهم قرار في المشروع كله وشرحه بالتفصيل في `cell2_other_class.py`.

أي حركة برّه القايمة (المشي مثلاً — مش موجود في NTU-60 أصلاً) المفروض
تترد `other` عن طريق عتبة الثقة، مش عن طريق كلاس مدرّب.

## بنية الملفات

الـ `.py` هي **المصدر الوحيد للحقيقة**. الـ `.ipynb` مولّد منها.

| ملف | الدور |
|---|---|
| `cell2_other_class.py` | اختيار الكلاسات وفلترة الـ annotations |
| `cell3_normalization.py` | تمركز على وسط الحوض، قياس بطول الجذع، 30 فريم |
| `cell4_split.py` | تقسيم Cross-Subject + augmentation |
| `cell5_model.py` | BiLSTM 256→128→128 + Dense — **متلمسش** |
| `cell6_eval.py` | تقييم على NTU + confusion matrix |
| `cell7_video.py` | تحميل فيديو الاختبار |
| `cell8_extract.py` | استخراج النقاط بـ YOLOv8n-pose |
| `cell9_smoothing.py` | نوافذ متعددة المقاسات + mirror TTA + معايرة + رفض |
| `cell10_timeline.py` | الـ ground truth والقياس الرقمي والـ sweep |
| `apply_edits.py` | يحقن الـ cells في النوتبوك |
| `fetch_results.py` | يسحب مخرجات الرن من Kaggle |

## التشغيل

python apply_edits.py && kaggle kernels push -p .

## ⚠️ تلات دروس مدفوع تمنها

**1. الدقة الإجمالية لوحدها مضللة.** أغلب الـ ground truth إجابته `other`،
فموديل بيقول `other` على الفيديو كله بياخد 35-86% حسب الفيديو. لازم تطبع
خط الأساس جنب أي رقم. الـ notebook بيعمل كده تلقائي في `cell10`.

**2. تقليل عدد الكلاسات بيزوّد المشكلة مش بيحلها.** جرّبنا 12 → 4 → 3 كلاس.
كل مرة NTU بتبقى أسهل (97.4% → 98.5% → **100%**) والـ softmax بيتشبّع،
فالمعايرة الحرارية بتتعلّق في قاع الشبكة والثقة بتبقى بلا معنى — وآلية
الرفض بتموت تماماً. في رن الـ 3 كلاسات، `phone_call` أخد 24 ثانية بثقة 97%
في فيديو مفهوش مكالمة خالص. **أي كلاس مالوش ولا إصابة صحيحة في فيديو
الاختبار بيتحوّل لسلة مهملات.**

**3. الـ ground truth الزمني ما يتكتبش من عيّنة أوسع من 0.5s** — ولا من
الذاكرة، ولا من وصف مكتوب قبل كده. كتبناه مرتين غلط من عيّنة كل ثانية
وقعدنا نفسّر أرقام كانت متقاسة بمسطرة مكسورة.
