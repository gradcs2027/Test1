## القاعدة الأولى هنا

**الـ `cells/*.py` هي المصدر الوحيد للحقيقة. الـ `.ipynb` ناتج مولّد منها.**

```bash
python apply_edits.py     # بيحقن الخلايا في lstm_ntu60.ipynb ويمسح الـ outputs
```

⚠️ **متعدّلش `lstm_ntu60.ipynb` بالإيد.** أي تعديل فيه هيتمسح أول ما
`apply_edits.py` تشتغل. السبب إن تعديل JSON مالوش diff مفهوم — الخلية
في ملف `.py` لوحدها بتبان في الـ diff سطر بسطر.

لو سحبت النوتبوك من Kaggle بعد رن، شغّل `apply_edits.py` قبل أي تعديل.

## إعدادات الـ inference (في `cell9_smoothing.py`)

| | القيمة |
|---|---|
| عتبة الرفض `CONF_REJECT` | 0.60 |
| تنعيم | moving average بـ `k=5` |
| `MIN_SEGMENT` | 2 نافذة |
| مقاسات النوافذ | 1.5 / 2 / 3 / 4 ثانية + mirror TTA |
| المعايرة الحرارية | grid search من 0.5 لـ 3.0 — الحالية **1.65** |

✅ التنعيم هنا **سليم**: `smooth_probs` بينعّم **الاحتمالات** لكل كلاس على
حدة وبعدين بياخد argmax. البق اللي كان بياخد متوسط حسابي لأرقام الفئات
كان في الـ baselines بس، مش هنا.

⚠️ **التطبيع لازم يكون واحد في التدريب والفيديو.** أي اختلاف بيكسّر
النتيجة. عشان كده `cell3_normalization.py` و `../shared/skeleton_norm.py`
لازم يفضلوا متطابقين — والاتنين اتقارنوا بالـ AST وطلعوا نفس الكود.

## درس اتقاس ولازم مايتكررش

**تقليل عدد الكلاسات بيضر مش بينفع.** اتجرّب 12 → 4 → 3 كلاس:

| | دقة NTU | الأداء على الفيديو |
|---|---|---|
| 12 كلاس | 97.4% | أحسن |
| 3 كلاسات | 100% | **أوحش** |

السبب: الـ softmax بيتشبّع، فالثقة بتبقى بلا معنى وعتبة الرفض بتموت.
**رجّعنا 10 كلاسات.** لو حد اقترح تاني إننا نقلل الكلاسات عشان الدقة
تطلع — ده الرد.
